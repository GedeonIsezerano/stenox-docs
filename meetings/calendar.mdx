## Connect Google Calendar

Open **Settings → Notetaker** and connect Google Calendar through the browser sign-in flow. The integration reads events; it does not create or edit calendar entries.

The default calendar is your primary calendar. To add another calendar you can access, enter its **Calendar ID** from Google Calendar settings. Stenox does not request a full calendar-list permission.

The current Google grant requests only `calendar.events.readonly`. Stenox does not request Google profile access or read your account name and email to identify the connection. Organizer and invitee details, including names and email addresses, can still be read from events.

No connection is required to start a meeting. Manual sessions remain available.

## Choose an event

In **New session**, browse or search ongoing and upcoming events. The picker starts with a seven-day window and can load more. Select an event to bring its title, agenda, times, organizer, invitees, and available links into the session.

Requests cover the selected calendars and date window, with an explicit event-field selection. The saved event can contain more information than the smaller context sent for insights, including location, event and join links, attendee details, and attachment metadata.

The event description stays in its own context section and does not overwrite Personal notes. Starting consumes the draft event selection, so the next shortcut recording does not silently reuse it. A blocked start preserves the draft.

Invitee names can help you label speakers manually. When a name is absent, the participant picker shows the email address instead. Assigning that participant to a speaker can save the email as the speaker label, which can then appear in conversation inputs. These labels do not prove attendance or identify voices automatically.

## Choose how context is processed

<Warning>
  Google-linked sessions and saved Google-derived context use your selected insights provider. Choose **On-device** for local insights. With **Codex**, **Claude Code**, or **Google Antigravity** selected, that provider can receive conversation, a Personal notes excerpt, included calendar and reference context, and information derived from them.
</Warning>

The speech provider is a separate choice. Select local speech too if you want meeting audio to remain on your Mac. Calendar context is background for the model, not evidence that someone said or agreed to an item.

Automatic reviews and **Generate insights** include the selected event's title (up to 500 characters), agenda (6,000), scheduled start/end and time zone, organizer name (120), and up to 100 invitee names (120 characters each). Dedicated email, location, event URL, join-link, and attachment-link fields are excluded from that calendar context. This does not remove emails used as speaker labels or personal information in free-form agenda, names, conversation, Personal notes, or reference text.

Refined notes and Ask use different inputs. They can include a calendar-derived session title or information already carried into outcomes, conversation, references, or provider context; they do not independently add the full event snapshot. See [the inputs for each operation](/meetings/processing#context-and-failures).

Attachment links can be opened in the browser. Stenox's Calendar permission does not include Drive file downloads. Download a file yourself and use [Add files](/meetings/references-and-ask) to import readable text.

## Reconnect and saved sessions

Saved event snapshots remain with the session after disconnecting. Reconnecting creates a new local connection identity and resets calendar selection. Older, broader grants may require reconnection; the app checks the returned scopes before use.

Disconnecting Calendar or removing its event does not erase information already carried into saved session content. Switching to On-device does not recall earlier cloud transfers or sign out the insights provider. Choose processing deliberately before generating; the app does not ask for fresh consent before each request.

**Outlook is not available in normal launches of this build.** Its implementation remains hidden pending publisher verification. A development acceptance switch is not public availability.
